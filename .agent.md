# MaliMart Engineering Agent

This agent is the repo-specific engineering guide for MaliMart, a Tanzanian marketplace built with React 19 + TypeScript + Vite + Tailwind v4, Supabase backend, and Vercel hosting.

## When to use this agent

- When editing MaliMart source code, fixing bugs, or adding features.
- When the task must obey MaliMart-specific conventions and live-app wiring.
- When choosing between default guidance and repo-specific patterns.

## What this agent does

- Treats the live app as the root-level directories (`/components`, `/pages`, `/context`, `/hooks`, `/services`).
- Avoids dead twins in `/src` except for the tiny set of known live files.
- Prefers subtraction, reuse, and unification over new surface area.
- Respects Supabase security via RPCs and RLS, never adding ad hoc client table queries in components.
- Uses the editorial Tailwind design system and UI primitives from `components/UI.tsx`.
- Verifies changes with the repo toolchain before and after edits.

## Key repo rules

1. Always read the actual file before touching it.
2. Resolve every referenced symbol before using it.
3. Trace imports both directions before deleting or importing code.
4. Prefer existing implementations over new ones; unify duplicate flows instead of creating a second path.
5. Do not delete files or run database DDL/migrations without explicit approval.
6. Do not add or rely on direct `supabase.from(...)` table queries in components; use `services/accountApi.ts` or the approved RPC layer.
7. Never assume `/src` is the live app; it is a partial dead twin.
8. Confirm UI primitives and props from the specific module being imported.
9. Use `components/UI.tsx` primitives (`Button`, `Input`, `Modal`, `ConfirmDialog`, `useToast`, `GraphicalTag`, `Badge`) before restyling.
10. Prefer the editorial theme tokens from `src/index.css` and the brand's typography system.

## Known traps

- `/src` is mostly stale. Only these files are load-bearing from `/src`:
  - `src/index.css`
  - `src/security.ts`
  - `src/hooks/useSellerStats.ts`
  - `src/hooks/useDebounce.ts`
  - `src/hooks/usePerformance.ts`
  - `src/services/aiService.ts`
- There are duplicate component names with different APIs. Verify the correct import before using.
- Migrations are hand-applied SQL files at the repo root. Archive them instead of deleting them.
- The public Supabase anon key is expected. RLS is the only security boundary.

## Verification checklist

- Run `npx tsc --noEmit` and confirm zero TypeScript errors.
- Run `npx vite build` and confirm the build succeeds.
- Check for dangling imports after edits.
- Keep security boundaries intact for cross-user data.
